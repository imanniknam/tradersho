# Owner email management

Independent Node service at `/owner-mail`, using the existing panel session cookie and the exact `OWNER_USER_ID` resolved from the designated existing account. No support-agent permission implies this role. Initial MFA enrollment and every operation require the current panel password. TOTP secrets are authenticated-encrypted, counters atomically reject replay, and PostgreSQL throttles attempts. Users manually enroll their authenticator; no QR secret is sent to a third party. Recovery requires a server administrator; no password reset bypass of MFA exists.

The root broker accepts only signed, fresh, nonce-protected requests via a restricted Unix socket. Supported operations: list accounts, create a `tradersho.com` account, update a mailbox password. It invokes the installed DMS CLI with an argument array and password on stdin, makes a private configuration backup first, and never exposes hashes. `notifications@tradersho.com` is reserved because changing it requires coordinated application/WordPress SMTP credentials. Mailbox deletion, domain/DNS/SSH management and arbitrary commands are not exposed.

Production: `/opt/tradersho-owner-mail`; compose uses the existing immutable app image only for its Node runtime/dependencies. It does not replace the client app. Broker: `tradersho-owner-mail-broker.service`; daily backup: `tradersho-owner-mail-backup.timer` at 03:15 UTC. Backups include the encryption/signing key, runtime configuration and a pg_dump of the owner MFA/audit tables. Existing full app/mail backups remain required. Archive/SQL, runtime.env, owner-key, snapshots and private account configuration must never enter Git.

`prepare.py` resolves the existing owner account by email and stores its stable ID. `publish.py` backs up and validates Caddy before routing the path; it refuses a repeated patch. The VPS Caddy template in this repository includes the same route. Rollback: restore its saved Caddyfile and validate/reload, stop only this compose project and broker; retain MFA state/key and audit records. Do not alter the primary app/mail containers.

Tests: `node --test deploy/owner-mail/security.test.mjs`; `qa-api.mjs` runs only in a disposable internal container with explicit fake OWNER_USER_ID/EMAIL, verifies owner scope, session/origin/password, enrollment, OTP replay and real broker listing, then deletes its fixtures. `qa-broker.py` makes a unique disposable mailbox, updates its password, waits for DMS changedetector, verifies TLS IMAP login, then deletes only that fixture. Never reuse these test scripts for a real customer's mailbox.

Operational limitation: successful DMS acceptance can take time to reload. A timeout is not a guarantee that no change happened; inspect state before retrying. SMTP/system mailbox rotation remains an administrator operation. The employer's own enrollment and first real-account action require their participation and are not claimed tested.
